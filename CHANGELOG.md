# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Chat archive and mark-as-read** through WhatsApp app-state patches:
  `Whatsmeow.archive_chat/3`, `unarchive_chat/3`, `mark_chat_read/3`,
  `mark_chat_unread/3`. Each returns `{:ok, collection_version} | {:error, reason}`
  and never raises. Follows Go whatsmeow's `BuildArchive` / `BuildMarkChatAsRead` /
  `SendAppState` — including that archiving also sends `["pin_v1", jid]` unpin.
  See [USAGE.md](USAGE.md).
  **Trial it on a spare number before a personal one:** the server cannot check an
  app-state patch's MACs, and nothing here has been run against a live account.
- App-state sync keys: `AppStateSyncKeyShare` from the phone is stored (only when the
  message is from our own account; a newer key replaces an older one, never the
  reverse), and missing keys are requested with `AppStateSyncKeyRequest`, at most
  once per key per 24 hours.
- App-state sync for `regular_low` (configurable): snapshot and patch fetch over
  `w:sync:app:state`, external-blob download, full MAC verification, per-collection
  version + LTHash persistence, and `Whatsmeow.AppState.sync/3`.
- Patch send with version-conflict handling: a `409` applies the server's patches and
  retries **once**.
- A pre-send self-check: every patch is decoded back and MAC-verified before it goes
  on the wire.
- `Whatsmeow.AppState.Store` behaviour with Postgres and in-memory implementations;
  `Whatsmeow.AppState.Coordinator` (per-device lock, key-request throttle).
- Test infrastructure: a Go vector generator (`scripts/app_state_vectors/`) that runs
  Go whatsmeow's real `appstate` package; a committed fixture of its output; an opt-in
  `go_interop` suite in which Go's decoder verifies this library's patches; and a
  fake WhatsApp server with an independently-verifying "phone".

### Fixed

- **App-state content MACs were wrong.** `Whatsmeow.AppState.Hash.content_mac/4` used
  `2` for SET and `3` for REMOVE as the operation byte; Go uses `byte(op) + 1` over a
  protobuf enum where `SET = 0` and `REMOVE = 1`, i.e. `1` and `2`. Every content MAC
  this library computed disagreed with what WhatsApp computes. It went unnoticed
  because the codec had no caller and its tests only round-tripped encode against
  decode, which shared the one wrong function. The codec is now pinned to vectors
  generated by Go itself.

### Changed

- The app-state codec (`Whatsmeow.AppState.Encode`, `Decode`, `Hash.update/3`) now
  works on the `SyncdPatch` / `SyncdMutation` protobufs as Go's does, instead of on
  loose byte fragments. Nothing in the library called the old functions.
- `Whatsmeow.AppState.Sync.build_fetch_patches_iq/4` addresses the IQ to the typed
  server JID rather than the bare string `"s.whatsapp.net"`, as `Whatsmeow.IQ`
  requires for the stanza to route reliably.
- Taking a snapshot (first sync, or `full_sync: true`) now clears the collection's
  stored mutation MACs along with its version. Go clears only the version, which can
  leave MACs for indexes absent from the new snapshot; a later patch would subtract
  them from an LTHash that never contained them and stop verifying.
- Persisting an applied patch is a single transaction (version, removed MACs, added
  MACs) rather than three writes.
- `Whatsmeow.Session` hands inbound key shares from our own account to
  `Whatsmeow.AppState.KeyShare` (one added call in the receive path; nothing else in
  send or receive changes).

### Known issues

- `Whatsmeow.Store.Postgres.delete_device/1` filters the three app-state tables on
  `our_jid`, but their column is `jid`. The resulting `undefined_column` is tolerated,
  so the statements are skipped: keys and versions still go through the foreign-key
  cascade, but `whatsmeow_app_state_mutation_macs` (no FK) survives a device delete.
  App-state sync is not affected — it clears those MACs before every snapshot — but
  the delete itself is incomplete. Not changed here; out of scope.
